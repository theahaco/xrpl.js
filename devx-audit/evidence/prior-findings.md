## Important corrections when reusing the prior narrative

- Claim 083 explicitly reports fetchMPToken and fetchMPTokenIssuance already exported from xrpl. Classify it as discoverability/typing, not absent functions.
- Claim 028 is a protocol capability/education limitation; claim 088 concerns Batch outer/inner outcome semantics. Do not present these as ordinary SDK correctness defects.
- Claim 004 headline includes Partial no-op, but its concrete reproductions establish keyof, Omit and typo behavior. Test utility types separately before repeating the broader claim.
- Claim 016 calls a temBAD_AMOUNT round-trip fee-charging. This reconciliation does not validate that assertion; do not carry it into a current impact claim without checking transaction result semantics.
- Claim 088 workaround equates txnNotFound with reverted; current guidance must account for validated ledger range/history availability before concluding final non-application.
- Old PLAN marks payment/escrow validators and Batch validation non-breaking; proposed PRs 42 and 41 use breaking-change titles. Compatibility must be reassessed on the actual proposed implementation.
- PR 55 body acknowledges an explicit simulate<true> type-argument compatibility break despite the original additive plan; this requires a migration note or adjusted overload design.
- PR 53 says nested tx_json.TransactionType checking does not narrow sibling meta and substitutes caller-defined predicates. Do not claim automatic event narrowing is delivered.
- PR 51 says known-command typo diagnostics can appear as command: never. Compile-time rejection alone does not establish an informative developer experience.
- PR 54 is based on PR 33 and additionally includes merged-in PR 38 commits; avoid double-counting dependency changes when reviewing its diff.
- Current report severity, compatibility, effort and commercial impact require fresh assessment. Preserve historical labels only as provenance.
